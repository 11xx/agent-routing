# Model era: Sonnet 5.5 enters on trial, max prohibited (2026-09-28 → )

Sonnet 5.5 entered the roster as an unmeasured trial row on the Claude
subscription, with its max tier prohibited. Opus 5.5 stays the head model and
holds every seat it held; nothing was reseated. The Sonnet name carries a bad
prior — `sonnet-5` measured dominated and token-hungry and is restricted to
relay shells — and this row inherits none of it and none of that row's
restriction: the build is tried on real work instead of assumed either way.

## What the entry rests on

Everything below is a launch-day observation from another evaluator's harness,
recorded with its evaluator so a rerun lands beside it as a new observation
instead of replacing it. None of it is a DeepSWE row, so none of it is in the
pass@1 column.

## Why max is prohibited

The ban is the operator's, and the launch record gives it four independent
reasons, so it is a decision about a tier rather than an unmeasured tier:

- Max buys 4 index points over xhigh (56 against 52) for 2.8x the cost per
  task ($7.60 against $2.74).
- Opus 5.5 xhigh reaches the same 56 for $3.46, so past xhigh a sideways move
  to Opus is cheaper than more Sonnet effort.
- It emits the highest output volume Artificial Analysis had measured, so the
  cash column understates wall-clock and window weight.
- On FrontierCode it scored below xhigh. More reasoning changed the agent's
  behavior — subagent fan-out, out-of-scope edits, timeouts — in a way that
  cost mergeable results, which makes effort a non-monotonic dial on this
  model, not a slower one.

`agent-routing check` refuses max under `sonnet-5.5`, `sonnet-5-5`, and the
callable id `claude-sonnet-5-5`, and `validate` refuses it as `prohibited`
even with `--allow-experimental`.

## Why no route was added

A roster row and a route are separate decisions, and only the first was made.
A profile is a standing default and a standing default needs a field record;
the row carries none. The path to the model is an operator-directed
selection —

`agent-routing validate --profile <shape> --backend claude --model sonnet-5.5
--effort <tier> --provider anthropic --reason <text> --allow-experimental`

— which records the execution shape, tier, pool, and reason against the route
version, so a trial is read against the exact selection that produced it. The
`anthropic` pool's `serves` set names the row, and the Claude backend's model
flag names `claude-sonnet-5-5`.

Tier statuses follow what a first trial needs. Medium and high are
probationary: medium is Claude Code's default, and high is the last tier
before the launch data stops paying. Low and xhigh are explicit-only, because
no case is made for either and xhigh is 2.5x high's cost for 5 index points. No tier is ranked; a
rank orders seated tiers and none is seated.

## What the trial has to answer

Field trials run on real work, recorded per session with the model, requested
and effective effort, harness, and evaluator; nothing here is generated by a
synthetic bench. In priority order:

1. **Sonnet 5.5 high against Opus 5.5 medium** on the same work: 47 at $1.08
   against 51 at $1.34 is close enough that accepted patches, repair rounds,
   wall time, window weight, output tokens, and scope discipline decide it.
2. **Medium against high**: whether high buys enough to be the production
   Sonnet tier.
3. **Xhigh against switching model**: whether Opus medium beats raising Sonnet
   effort on the slices high cannot land.
4. **Review calibration**: the same flawed and clean diffs, counting serious
   defects found and missed, false alarms, whether the verdict was right, and
   whether extra effort added noise instead of signal.

## What this pass deliberately leaves

- No pass@1 row, no field arc, no review round, no approval, no observed
  quota weight on the Claude subscription. API price and benchmark cash are not
  window consumption.
- No profile, variant, or default anywhere; the row is reached by naming it.
- The `sonnet` alias. The Claude client documents it as the latest Sonnet, and
  the relay shells pin it at low; whether that resolves to this build, and
  what the `sonnet-5` row should say once it does, is a separate decision.
- Any division of work between Claude tiers by window weight; that follows
  from measured consumption, not from list prices.
